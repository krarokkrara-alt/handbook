# Independent verification — ภาพจริงและเนื้อหา EV handbook

วันที่ตรวจ: 9 พฤศจิกายน 2569 • ผู้ตรวจ: independent verifier agent

## สถานะรอบแรกก่อน integration (บันทึกย้อนหลัง)

รอ manifest `researched-components.json` และ `researched-systems.json` และรอตรวจฉบับ integration ใหม่ รายงานนี้ยังไม่ใช่การรับรองว่าครบ 2 ภาพจริงต่อหน้า

ต้นฉบับปัจจุบันก่อน integration มีภาพถ่าย C เพียง 1 ภาพ (หน้า 33) และ schematic จริง A เพียง 1 ภาพ (หน้า 32) ภาพ B เป็นภาพวาดหลักการ ไม่นับเป็นภาพถ่ายจริง กรอบรอภาพไม่นับเป็นภาพจริง

## เกณฑ์ตรวจทุกภาพ

1. ไฟล์เปิดได้ เป็นภาพจริงจากแหล่งตรวจสอบได้ ไม่ใช่ AI, ภาพ 3D render หรือ stock ที่อ้างเป็นอะไหล่เฉพาะรุ่น
2. ชื่อผู้สร้างและหน้าต้นทางตรงกับไฟล์ มี license ที่ครอบคลุมรูปนั้น รวม attribution และเงื่อนไขการแก้ไข/ShareAlike ตามจริง
3. ภาพ hobby/development board ต้องติดป้ายเช่นนั้น ไม่เรียกเป็น VCU/BMS/OEM ECU รถโดยไม่มีหลักฐาน
4. Caption ระบุสิ่งที่มองเห็นจริง ไม่อ้างจุดต่อ/เลขขา/หน้าที่ภายในที่ไม่ได้ยืนยันจากภาพหรือเอกสาร
5. ภาพสภาพปกติไม่เป็นหลักฐานว่าชิ้นงานเสีย และภาพประกอบไม่อ้างเป็นรถในกรณีศึกษาอิงเอกสารหรือสมมติ
6. วงจรจริง A และรูปคลื่นวัดจริงต้องแยกจากภาพถ่าย C; ภาพวาด B ไม่นับเป็น actual photograph
7. แต่ละหน้าต้องมีอย่างน้อย 2 ภาพจริงที่แตกต่างกัน โหลดได้ และตรงเรื่อง การ crop/ซูมไฟล์เดียวไม่นับเป็นสองภาพหลักฐานอิสระ
8. นับจำนวนรูปต่อหน้าและจำนวนไฟล์ไม่ซ้ำทั้งเล่มแยกกัน การซ้ำต้องไม่ทำให้คำบรรยายหลอกว่าเป็นชิ้นงาน/รุ่นอื่น
9. ตรวจฉบับจัดหน้า: caption อ่านได้ ไม่ตัดเครดิต ภาพไม่ผิดสัดส่วน ไม่เล็กจนมองประเด็นไม่ได้ และไม่มีองค์ประกอบล้นหน้า

## ผลสอบทวน DTC ที่ต้องตรวจซ้ำหลัง integration

ตรวจ source `build-handbook.cjs` รอบถัดมาแล้ว: ข้อแก้ Toyota 38/45, ขอบเขต MHEV 41/S14, ป้ายรายการ GM 40 พร้อม HPCM2/รุ่นปี และ subcode 37 ถูกแก้แล้วใน source รอตรวจไฟล์ HTML/PDF ที่ rebuild และตรวจคำบรรยายประกอบภาพใหม่

- หน้า 38/45: T-SB-0049-14 Rev1 กำหนดการเปลี่ยน HV Battery Assembly เมื่อเข้าเงื่อนไข (A หน้า 4 ข้อ 3 / B หน้า 8 ข้อ 4) ต้องไม่ย่อจนดูเหมือนทำความสะอาดพัดลมอย่างเดียว
- หน้า 41/42 และ S14: แหล่ง U-code เป็น 2022 Wagoneer 5.7L eTorque (MHEV) ต้องเปิดเผยขอบเขต ไม่อ้างเป็นหลักฐาน BEV
- หน้า 40: P1FFF/P1F0E/P0DAA ยังขาดนิยามฉบับตรงรถ ควรติดป้ายรายการที่ต้องเปิด GM service information เพิ่มเติม และบอก HPCM2/รุ่นปีที่ยืนยันจาก S5
- หน้า 37: เปลี่ยนข้อความบังคับมีรหัสย่อยเป็นเก็บ subcode/INF เมื่อระบบ/เครื่องมือรองรับ

## รอบตรวจ systems manifest (ก่อน integration)

metadata มี 27 รายการ โดย 5 รายการมีไฟล์ ณ รอบตรวจ:

- ผ่านภาพและ subject แบบมีขอบเขต 4 ภาพ: SYS75308683, SYS157506859 (LEAF ภายนอก ไม่ใช่รถ DTC/น้ำท่วม), SYS20709410 (สถานที่ชาร์จในอดีต), SYS45826314 (หัว AC Type 2 ไม่ใช้ยืนยัน pinout)
- **ปฏิเสธไฟล์เสีย 1 ภาพ: SYS76762500** เปิดดูได้เฉพาะส่วนบนประมาณ 40% ส่วนล่างเป็นสีเทา ต้องดาวน์โหลดใหม่หรือกันออก แม้เครื่องมือรายงาน decoded/loaded สำเร็จก็ไม่ถือว่าผ่าน
- 22 รายการยังไม่มีไฟล์ จึงยังไม่ผ่าน visual verification

metadata ของภาพ NiCd leakage สองภาพแก้ scope แล้ว ไม่แนะนำเป็นภาพน้ำท่วม และ Fluke115 เก็บ required attribution User:Typhoon แล้ว

รอบเพิ่ม Adafruit: ตรวจภาพ SYSA4759 / SYSA5724 / SYSA5708 และ README + license.txt ของแต่ละ repository แล้ว ผ่านเป็นภาพบอร์ดพัฒนา CAN จริง (CC BY-SA 3.0) ไม่ใช่ ECU รถ ต้องคงป้ายขอบเขตและ attribution. SYSA5708 ต้องเรียกตัวเลือก termination ว่า **สวิตช์ ON/OFF** ไม่ใช่ jumper ตามรูปและ README (แจ้ง researcher แล้ว)

สรุปรอบก่อน integration ล่าสุด: components 27 ภาพที่ researcher เลือก eligible ผ่านแบบมีขอบเขต หลังแก้ caption และ exclude cmp13/32/33; systems Commons 4 ภาพผ่าน + Adafruit 3 ภาพผ่าน = **34 ภาพพร้อมใช้แบบมีขอบเขต** ยังไม่รวมภาพ Adafruit เดิมในหนังสือ และยังไม่ใช่การรับรองจำนวน 2 ภาพต่อหน้า

ตรวจ JPEG EOI ของไฟล์ที่มีใน assets/real-images: เฉพาะ sys-76762500.jpg ไม่มี FF D9 ท้ายไฟล์ ยืนยันว่าไฟล์ขาด ไม่ใช่เพียงความผิดพลาดของตัวแสดงภาพ

## รอบเพิ่ม foxBMS และ CAN controller

- foxBMS cmp44–50, cmp52–53: ผ่านภาพถ่ายจริง 9 ภาพและสิทธิ์ CC BY 4.0 Hardware/Documentation จาก LICENSE.md ที่ตรวจผ่านหน้า GitHub โดยตรง พร้อมเทียบ cabling.rst / bjb.rst เรื่อง Master, Extension I/O, SPI–isoSPI Interface, Slave วัดแรงดัน/อุณหภูมิ/passive balancing และ BJB current sensor/contactors/precharge
- cmp51: ผ่านเป็น documented reference circuit ของ foxBMS ไม่ใช่ภาพถ่าย ไม่นับจำนวนภาพจริง
- cmp46/cmp47 เป็นภาพฐานเดียวกันแบบไม่มี/มีคำกำกับ และ cmp52/cmp53 เป็นคู่ภาพ BJB ที่ต้องนับกลุ่มเดียวต่อหน้า คง duplicateGroup และห้ามใช้คู่เดียวกันเพื่อเติมขั้นต่ำสองภาพ
- SYSA5709 / SYSA5728: ผ่านภาพจริง CAN controller MCP2515 พร้อม transceiver แยก มี README/license CC BY-SA 3.0 และ attribution ครบ ไม่ใช่ ECU รถ

จำนวนไฟล์ภาพถ่ายที่ผ่านแบบมีขอบเขต ณ รอบนี้: components 36 + systems Commons 4 + Adafruit ใหม่ 5 = **45 ไฟล์** (43 ภาพฐานอิสระเมื่อหักคู่ derived สองกลุ่ม) ยังไม่รวมภาพ Adafruit BFF เดิม จำนวนนี้คือคลังไฟล์ ไม่ใช่จำนวนตำแหน่งในหนังสือ ต้องตรวจอย่างน้อย 2 ภาพต่อหน้าหลัง integration อีกครั้ง

## ผลสุดท้ายหลัง integration — ผ่านแบบมีขอบเขต

ตรวจฉบับ HTML/JSON/PDF ที่รวมภาพแล้ว และตรวจ `image-placements.json` ครบ **100 ตำแหน่งคู่ภาพใน 50 หน้า** จาก **37 ไฟล์ภาพที่ใช้จริง** แยกจากคลังภาพที่ค้นได้ทั้งหมด ผ่าน 50/50 หน้า โดยแต่ละหน้ามีภาพถ่ายจริงที่ต่างกันอย่างน้อย 2 ภาพ ไม่มีการใช้ภาพ derived สองรูปจากกลุ่มเดียวกันเติมขั้นต่ำในหน้าเดียว

ผู้ตรวจได้ดูภาพต้นทางที่ใช้ทั้ง 37 ไฟล์ และทวน caption ทั้ง 100 ตำแหน่งเทียบกับเรื่องและขอบเขตแหล่งภาพ ตรวจเทียบ SHA-256 กับ final manifest ไม่พบไฟล์หายหรือ hash ไม่ตรง ไม่มีภาพเสีย SYS76762500 หรือภาพสิทธิ์กำกวม cmp32/cmp33 ในฉบับใช้จริง

ตรวจตัวอย่างการจัดหน้าด้วยสายตาจากภาพ preview หน้า 1, 3, 32, 37, 42 และ 43 และอ่านผลตรวจ layout ทุกหน้าใน `verification.json` ซึ่งระบุ PDF 50 หน้า A4 ไม่มีเนื้อหาชน footer ไม่มีภาพโหลดไม่สำเร็จ และไม่มี SVG text ออก viewBox. การตรวจนี้ไม่ใช่การรับรองความอ่านง่ายของตัวพิมพ์ทุกขนาดบนกระดาษทุกเครื่องพิมพ์

ข้อแก้ที่ตรวจยืนยันแล้ว:

- cmp04 เป็นช่องรับชาร์จ LEAF ไม่เรียกเป็น OBC
- cmp31 เป็นชุดขับเคลื่อน e-Golf ตัดแสดง ไม่เรียกห้องเครื่อง
- cmp18 เปลี่ยนเป็นชุดขับเคลื่อน Aisin จัดแสดง ไม่อ้างว่าภาพปิดฝาเป็นชิ้นงานตัดแสดง
- cmp50 ใช้คำวัดอุณหภูมิ ไม่ระบุ NTC ที่แหล่งไม่ได้ยืนยันเฉพาะ
- CAN Pal ใช้คำสวิตช์ termination ตามภาพ
