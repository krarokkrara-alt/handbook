# คำสั่งงาน Claude AI สำหรับหนังสือ BCM MyTech

## เป้าหมาย

ทำงานต่อในโฟลเดอร์นี้เท่านั้น เพิ่มความลึกของหนังสือ BCM เรื่องวงจรในบอร์ด โปรแกรมอ่านเขียน การย้ายชิปและข้อมูล/โคลน ครอบคลุมญี่ปุ่น ยุโรป อเมริกา ให้มีภาพจริง วงจร และขั้นตอนพร้อมเกณฑ์ดี–เสียและแสดงผลต่างอย่างตรวจสอบได้ ใช้ภาษาไทย ไม่หยุดเพียงทำโครงหรือรวบรวมลิงก์

## เริ่มต้น

อ่าน README.md, manuscript.md, supplement-v2.md, QA_REPORT.md, EDITORIAL_REVIEW_V2.md, VISUAL_SOURCES.md และ FIGURE_MANIFEST.json ตรวจว่าประเด็นใดมีอยู่แล้ว ห้ามนับภาพเดิมหรือความสามารถเดิมเป็นข้อมูลที่ค้นเพิ่ม สร้าง reports/PROGRESS.md บอกงานที่ทำจริงและหลักฐานที่ยังขาด

แยกงานผู้ค้นวงจร ผู้ค้นโปรแกรม และผู้ตรวจอิสระ หากสภาพแวดล้อมรองรับ Agent ให้มอบหมายแยกกัน แล้วให้บรรณาธิการตรวจรวม ไม่อ้างว่าเป็นการรับรองจากวิศวกรหรือผู้ผลิตรถ

## งานที่ 1 ค้นวงจรเพิ่มจากภาพบอร์ดที่มี

1. เริ่มจาก Lexus Body ECU, BMW FRM และ GM BCM ในภาพเดิม ค้นฉลาก เลขอะไหล่ PCB revision และภาพสองด้านที่สัมพันธ์กัน อ่าน marking ชิปที่มองเห็นจริง ถ้าไม่ชัดให้บอกว่าไม่ชัด ไม่เดาจากรูปร่าง
2. หา datasheet/application note จากผู้ผลิตชิปและคู่มือรถตรงรุ่น เทียบ package, pinout และ suffix ให้ครบ เพิ่มวงจรย่อยที่ยังไม่มีหรือเพิ่มรายละเอียดที่ขาด เช่น regulator/supervisor, high-side/low-side, driver diagnostics, CAN/LIN, EEPROM/MCU memory และเส้นทาง wake
3. ภาพวงจรแต่ละภาพต้องบอก document ID, revision, page/figure, URL, วันที่ตรวจ และความสัมพันธ์กับบอร์ดจริง แยก schematic ผู้ผลิตชิปออกจาก schematic ของกล่องรถ ห้ามเรียกสองอย่างนี้แทนกัน
4. หากถอดวงจรจากภาพ ให้แยกเน็ตที่มีหลักฐานกับส่วนที่ยังต้องวัด continuity ชัดเจน เพิ่มจุดวัดโดยไม่เปลี่ยนการเชื่อมต่อเดิม ห้ามสร้างค่าตัวต้านทาน เบอร์ชิป หรือขาปลั๊กที่ไม่มีหลักฐาน
5. แต่ละวงจรต้องมีขั้นตอนวัด สภาวะไฟ/enable/wake/โหลด จุดอ้างอิงกราวด์ ค่าหรือช่วงที่ใช้ตัดสินจากเอกสาร และตารางผลปกติ–ผิดปกติ–ยังสรุปไม่ได้ พร้อมลำดับแยกโหลด/อุปกรณ์ก่อนตัดสินว่า IC เสีย

## งานที่ 2 ภาพจริงและโปรแกรมย้ายข้อมูล

ค้นเอกสารผู้ผลิตเครื่องมือ CG100X, CG-PRO, ACDP และเครื่องมืออื่นที่รองรับ BCM ตรงรุ่น ใช้เครื่องมือเท่าที่มีหลักฐาน ไม่จำเป็นต้องใส่ครบทุกชื่อ เพิ่มภาพหน้าจอจริงพร้อมเวอร์ชันและคำอธิบายเมนู ไม่สร้างหน้าจอปลอมหรือปุ่มที่ไม่มีจริง ไม่ใช้ภาพงานมาตรวัด airbag หรือ ECU เครื่องยนต์เป็นภาพสอน BCM

ทำกรณีละเอียดอย่างน้อยหนึ่งกรณีที่หลักฐานครบก่อนขยายจำนวน เป้าหมายเริ่มต้นคือ CG-PRO/CG100X และ ACDP FRM แยกขั้นตอนต่อไปนี้ตามขอบเขตที่คู่มือรองรับ:

1. ระบุเลขกล่อง MCU/EEPROM/mask และเป้าหมายว่าอ่านสำรอง กู้กล่องเดิม ย้ายชิป หรือเปลี่ยนกล่อง
2. ตรวจเครื่องมือ เวอร์ชัน สิทธิ์ใช้งาน อะแดปเตอร์ ผังตรงชิป และแรงดัน อย่าใช้แรงดันเข้าตัวเครื่องแทน VCC ของชิป
3. ตรวจการต่อและการสัมผัสก่อนอ่าน สำรองพื้นที่ EEPROM/D-FLASH/P-FLASH ตามที่เครื่องมือรองรับจริง เก็บไฟล์ชื่อแยกพร้อมขนาด/hash
4. อ่านซ้ำและเปรียบเทียบ ก่อนทำคำสั่งที่อาจลบข้อมูลหรือเปลี่ยน partition/decrypt ต้องมีหลักฐานผลกระทบตรงชิป ห้ามทดลองคำสั่งเหล่านี้กับต้นฉบับที่ยังไม่สำรอง
5. สำรองกล่องทดแทนก่อน ตรวจความเข้ากันได้ของ HW/SW/พื้นที่ข้อมูล ย้ายเฉพาะขอบเขตที่มีวิธีตรงรุ่น ไม่ถือ read-write coverage เป็น full clone
6. อ่านกลับหลังเขียน เปรียบเทียบกับไฟล์ที่ตั้งใจเขียน ระบุว่าตรวจด้วยฟังก์ชัน verify ของเครื่องหรือเทียบ read-back ด้วยวิธีอื่น
7. แยกผลโปรแกรมชิปออกจาก coding/adaptation/relearn และทดสอบบนรถตามคู่มือที่ตรงรุ่น ไม่มีผลจริงให้ระบุว่ายังไม่ทดสอบ

หากไม่มีเครื่องมือหรือชิ้นงานจริง ให้เรียกส่วนนี้ว่าแนวทางจากเอกสาร ห้ามแต่งภาพ success log หรือผลซ่อมหาย

## งานที่ 3 แสดงผลต่างให้ชัด

ใช้ tools/compare_data.py กับไฟล์ที่เจ้าของอนุญาตและมีจริง ทำตาราง 3 คู่เมื่อมีข้อมูล: การอ่านรอบ1กับรอบ2, ไฟล์ตั้งใจเขียนกับ read-back, และก่อนกับหลังซ่อม/ย้าย ระบุขนาด SHA-256 จำนวนไบต์ต่าง ช่วง offset และข้อสรุปที่หลักฐานรองรับ

ช่วง offset ที่ต่างไม่ได้บอกหน้าที่ของข้อมูลโดยอัตโนมัติ ห้ามกล่าวว่าเป็น VIN, key, checksum, coding หรือข้อมูลประจำรถ หากไม่มีเอกสารหรือหลักฐานยืนยัน ห้ามโพสต์ dump, กุญแจเข้ารหัส ข้อมูลระบุตัวรถ/บุคคล หรือ bytes ที่เป็นข้อมูลลับลงคลังสาธารณะ

ถ้าไม่มี dump จริง ให้ทำตัวอย่างจำลองและติดป้ายว่า ข้อมูลจำลองเพื่ออธิบายการเปรียบเทียบ ห้ามนำมารายงานเป็นผลโคลนจริง เพิ่มตารางเปรียบเทียบวิธีหนีบอ่านในวงจร ถอดอ่าน ย้ายชิป เขียนข้อมูล และตั้งค่ากล่องทดแทน พร้อมข้อดี ข้อเสีย เงื่อนไขเหมาะสม และจุดหยุดงาน

## หลักฐานและสิทธิ์ภาพ

เก็บทะเบียน research/SOURCES.csv มี URL ผู้จัดทำเอกสาร document/revision/page วันที่เข้าถึง รุ่นกล่อง/ชิป ประเภทหลักฐาน และสิทธิ์ภาพ ใช้ภาพจริงก่อน ถ้าต้องวาดให้บอกว่าเป็นภาพวาดและอ้างอะไร ภาพไม่ชัดหรือสิทธิ์ยังไม่ทราบให้ระบุ อย่าอ้าง public domain เพียงเพราะดาวน์โหลดได้หรืออยู่บน NHTSA

จุดที่ต้องระวังจากงานเดิม: TPS1H100 version A/ST กับ B/CS ต่างกัน; ภาพ ACDP XDT256 ใช้แทน XEQ384 ไม่ได้; CG-PRO MCU ตัวอย่างเป็น MC9S12DG64 80QFP; ภาพ Hex Compare ที่ต่างกันไม่ใช่ verify ผ่าน; CAN termination อย่างเดียวไม่ใช่วงจร transceiver ครบชุด
